# 资产再平衡 + 资产转换规划

用来算「手上的资产该卖多少、该买多少」的一个小工具。纯前端，单页，不需要服务器。

## 现在是什么状态

目前是**原页面原样搬过来的版本**，功能没变，只是加了移动端 viewport，方便先放上网用手机验证。
真正的重构在后面的阶段做。

## 已知问题（按修的顺序排）

这些是已经确认存在的，不是猜的：

1. **默认 3 个资产时比例是 33/33/33，合计 99%，第一次点「计算」必然报错**
2. **当前市值和当前价格从来没被保存** —— 刷新页面或点「重新生成」就全部变回默认值
3. **金额用浮点数**，`round2` 也不可靠（`10.075` 会算成 `10.07`）
4. **独立四舍五入会丢 1 分钱**，账对不上
5. **负价格、负市值、负比例都不拦截**
6. **卖出侧完全不收手续费**（代码里注释自己写明了）—— 会高估可用资金
7. **资产名会被拼进 HTML**，名字里带 `<` 或 `"` 会把页面弄坏，而且存下来之后每次打开都可能触发
8. **资产数量没有上限**，填大了会卡死手机

完整的缺陷清单和判定过程见 git 提交历史。

## 已经定下来的产品语义

- **买入手续费**：额外掏现金补（不是从卖出款里扣）。界面上会拆成「净买入额 / 手续费 / 实际掏现金」三列，方便核账。
- **卖出手续费**：每个资产一栏，**默认 0**。C 类基金本来免赎回费；A 类或持有不满 7 天的自己填。
- **份额**：只做估算，保留两位小数，不保证能整除到可下单的最小单位。界面会写清楚这一点。

## 开发方式

- 计算逻辑放在 `core.js`，纯函数，不碰 DOM、不碰 localStorage
- 测试用 Node 自带的 `node --test`，零依赖
- 跑测试：`node --test`

## 怎么在手机上用

打开 Pages 地址 → 浏览器菜单 → 添加到主屏幕。
